# 博客优化实施计划

日期：2026-11-16。基线：前台 `1322780`，后台 `fac700d`。两个仓库分别交付，禁止直接推送 main。本计划取代原诊断中的分类批量重建、作品集和统计明细清理建议。

## 已确认的范围

保留技术实践与生活随笔定位。新同步笔记默认私有，发布状态、技术笔记/随笔类型由后台维护；同步继续维护正文、分类和标签。既有 slug 和首次发布时间保持稳定。Post、Note 不合并，全库外键模式不切换，PageView 不删明细，不清理幂等记录。

## 接口契约

列表默认 current=1/pageSize=10，最大 50，保留 size 别名，以 pageSize 优先。非法参数 400。返回 ok/data/total/current/pageSize/pages。q 同时搜索标题和正文，先应用可见性条件。摘要不含 content；详情独立读取。scope=admin 需要管理员 JWT，管理响应 no-store。

更新省略字段保留，null 清空分类、标签或系列关系。published 仅布尔值。首次公开时只在 publishedAt 为 null 时写入；隐藏与再次发布保留。数据库故障 503，不伪装 404、不暴露 SQL。409 明确区分 slug、幂等、同步身份和占号冲突。

自动 slug 先做字符规范化、无声调拼音转换、英文小写及连字符整理，基础部分最多 120 字符；空结果使用资源前缀和随机标识。手填仅小写英文、数字、分隔连字符，最多 160 字符。候选为基础值、-2、-3、两次独立随机八位十六进制后缀。仅对应 slug 唯一键冲突换候选，不扫描前缀，不重复 AI 准备。标题编辑与同步不修改已有 URL。

创建幂等范围为资源/管理员/UUID 键，规范化请求 SHA256 和成功结果持久化。同键同请求重放，同键不同请求 409，内容已删 410。内容和结果在同一事务提交。MySQL P2034 死锁最多五次重新执行已回滚的数据库事务，AI 准备只做一次；其他数据库错误不换 slug、不重跑外部服务。客户端失败后重试沿用键，修改内容或成功后换键，不自动重试 POST。

## 正式发布顺序

1. 在独立恢复环境验证备份可以恢复，核对新增迁移 SQL、历史公开数量和 URL。保留恢复记录及当前安全版本。
2. 先发布 header 身份验证等兼容能力，再发布后台凭据和详情读取适配；在短暂管理维护窗口部署强制鉴权、幂等创建和旧 URL token 接口停用的完整 API。不要用旧后台操作新 API，也不要用新动态草稿界面向旧 API 创建内容。
3. 新增兼容结构后先执行摘要回填 dry-run，再在审核后 --apply；核对公开时间与动态历史数量，再切换应用读取。不得编辑旧迁移。
4. 列表摘要切换前让所有调用方按需读详情，随后删正文列表返回。
5. 每阶段 PR 检查通过、评审与验收后才合并。GitHub production 环境和迁移就绪变量在备份恢复/后台兼容确认后启用；不能只凭一次本地构建上线。

生产服务绑定 127.0.0.1，Nginx 必须覆盖 X-Real-IP，并阻止绕过代理直达应用。完成代理核查后设置 TRUST_PROXY=true；未开启时不信任客户端来源 header，采用共享保守限流。默认 PV_RATE_LIMIT=120、HEARTBEAT_RATE_LIMIT=180。Redis 故障返回 503，不回退无限全库查询。缓存累计数 60 秒，在线数实时。

## 回滚与发布前剩余工作

回滚保留新增表/字段、幂等记录和历史明细。回滚到已验证的安全应用版本，不能退回匿名写入或草稿可读的版本。资料还原、内容发布状态修改和数据迁移不得通过批量隐藏非技术内容实现。

正式内容审计按用户决定留到发布前：使用只读连接运行 privacy-audit.ts 输出所有既有公开内容的待审清单，在后台逐项决定；不读取或公开正文、不自动隐藏。曾被纳入源码/跟踪配置的凭据在上线前轮换，移除 Git 跟踪不等于移除历史泄露。

自动化、隔离联测与生产只读检查分开记录。七牛真实上传、正式备份恢复、生产代理边界及既有内容审计需要发布环境验收，本地测试不得代替。
