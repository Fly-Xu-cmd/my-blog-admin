## 阶段评审

阶段 PR 依次建立在上一阶段分支上。新增兼容数据结构和安全正文渲染公共基础放在阶段 1；阶段 2 切换服务端列表并移除列表正文；阶段 3 增加系列 API/页面/管理入口；阶段 4 补齐统计缓存、阅读入口、清理和 CI。每个阶段分别进行类型/构建和对应测试核验；PR 不自动合并，生产部署需要就绪变量和环境验收。

第一阶段先提供 header 验证的兼容提交，再切入完整安全版本；后台适配在 API 强制停用旧接口前发布，期间保持管理维护窗口，避免旧动态 API 忽略草稿标志。各阶段上线前必须验证跨仓兼容。
