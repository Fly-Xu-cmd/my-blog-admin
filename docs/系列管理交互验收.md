# 系列管理交互优化

## 变更目的

原页面需要在弹窗中输入文章 ID 排序，每次打开排序还会分页读取全站文章。改为左侧选择/搜索系列，右侧在“文章编排”和“系列信息”之间切换，直接安排阅读顺序。

## 影响范围

- 复用 Ant Design 的搜索、表单、标签、下拉菜单、提示及封面占位控件；页面色彩使用主题令牌。
- 拖动手柄、上下移动、移至开头/末尾均可排序；手机和键盘操作使用按钮。草稿参与完整编排，公开页继续只展示已发布文章。
- 信息与顺序分别保存。信息保存保留未提交的排序，保存失败保留本地改动。切换系列、刷新/重试列表、离开页面有修改保护；干净状态不注册离开阻止器，身份过期仍能进入登录。
- 新增 API `GET /api/series/:id/posts`：先验证管理员 JWT，仅查该系列，返回有序完整成员摘要（包含草稿，不包含正文），不存在返回 404，数据库故障返回 503，响应 no-store。
- 重排继续使用已有完整成员集合校验、系列锁和事务；成员发生变动返回 409，提示重新载入。文章新增/移出系列沿用文章编辑入口。本次不增加模型或改动已有 URL。

## 风险与回滚

先发布新增 API，再发布后台；旧后台与新增 API 兼容。API 未就绪时新后台明确显示加载失败，不回退全站扫描或把缺失数据当作空系列。服务端不变更已发布状态、slug 或系列成员；排序只有显式保存才写入。

需要回滚时，后台回退到上轮已评审版本，保留新增只读 API。没有数据库迁移，无需删除字段或修改数据。前台/API 和后台的无关锁文件、工作流及依赖调整不纳入本轮提交。

## 系列路径自动生成（2026-11-18 增量）

新建系列只需填写名称，路径留空时由 API 使用统一 slug 工具转换为无声调拼音和英文，例如“博客工程实践”生成 `/series/bo-ke-gong-cheng-shi-jian`。路径字段仍可手填小写英文、数字和连字符，后台省略空 slug。创建后路径固定，修改名称继续使用旧路径。

API 先鉴权并验证名称/简介，再尝试写入；仅 slug 唯一键冲突进入最多五个候选的分配，系列名称冲突仍返回 409，不换名重试。手填路径冲突返回 `SLUG_CONFLICT`。没有新依赖或数据库迁移。

实施会话验证：隔离 Vitest 35 项通过，新增 5 项覆盖中文/混合名称、自动后缀、手填优先/撞名、名称冲突单次写入、改名保持路径、非法路径和匿名拒绝；后台 Jest 18 项通过，新增留空创建、手填校验及失败保留输入后重试。两仓类型检查、前台 lint 与后台任务文件 Biome 通过，前后台生产构建通过。浏览器检查新建表单路径可选、名称输入与撤销，未向演示库保存系列；预览截图为根工作区 `.reviews/series-auto-path.jpg`。生产审计仍留到发布前。

发布仍先 API 后后台：新版 API 兼容旧后台手填，新后台留空生成依赖新版 API。若回退 API，先回退后台以恢复路径必填；既有路径不需要回填或修改。自动生成创建成功后的响应丢失仍按现有系列创建流程提示失败，不增加自动 POST 重试。

本增量独立只读评审继续复用原评审会话，源码及定向 diff 检查通过，确定阻断 0 项；测试和构建由实施会话完成。
